# Banzai 2.3.0

Release following [2.2.2](2.2.2.md), with project adoption and interactive setup
under [ADR-0040](../decisions/0040-project-adoption-preflight-and-interactive-setup.md).
This source candidate uses the release owner's selected version **2.3.0**.

## Compatibility and migration

This release includes compatibility changes despite the selected minor version:

- `banzai doctor --json` emits `banzai-doctor/v2` with `schemaVersion: 2`, adding
  `project.guidance` immediately after `repository.git`. Update consumers that
  require v1 before upgrading. Historical v1 reports retain their identity.
- New workflows require populated root `PROJECT_MANIFEST.md` and compatible
  root project instructions. Existing unadapted projects must complete explicit
  setup before starting another task; existing adopted projects with populated
  guidance retain their setup readiness.
- Published workflows recheck instruction layout before model attempts. A
  refusal preserves durable checkpoints and decisions. For an unfinished run,
  repair guidance manually outside CLI setup, then resume; alternatively,
  explicitly cancel the run before using `banzai setup`.

For a new or unadapted project, initialize Git if needed, run `banzai init` or
`banzai setup`, explicitly invoke the installed project-manifest skill, and
review its proposed guidance. Review and commit project files before starting
a workflow. Setup itself supports a Git repository without an initial commit.

## Changes since 2.2.2

- `banzai init` offers project setup after model selection. Direct
  `banzai setup` launches the installed and enabled `banzai:project-manifest`
  skill in a selected foreground Codex or Claude Code client, preserving the
  terminal and ordinary client permission controls.
- Setup reports all three root guidance files, explains plugin prerequisites,
  offers manual instructions when a client is unavailable, and reinspects
  guidance after the client exits. It never submits a task automatically.
- Missing Git and missing initial commit now produce actionable diagnostics.
  Fresh model selection says `Use default`; repeat initialization retains
  `Keep` for saved choices.
- Project-guidance inspection is read-only and bounded. Workflow refusals do
  not create synthetic failed attempts or discard saved approvals.
- Maintainer PTY tests require `python3` on `PATH` with its standard library.
  Missing Python fails the suite; deterministic CI lanes check its presence.
  Python is not a CLI runtime dependency.

## Requirements and delivery

Supported hosts and Node lanes remain those in
[2.2.2](2.2.2.md#requirements-and-installation): macOS or Linux, Node.js
22.20.0+ within major 22 or 24.11.1+ within major 24, Git, and supported
subscription-authenticated clients. Automatic setup requires the Banzai plugin
to be installed and enabled in the selected client.

The plugin and orchestrator share source version **2.3.0**; their installation
and publication remain separate. This version update does not establish npm
publication or installed-client delivery. Codex and Claude Code interactive
confirmation (C7) remains **unverified** in the
[Private work history](../historical-references.md).
Verified publication facts belong in the
[delivery record](public-publication.md#delivery-record).
