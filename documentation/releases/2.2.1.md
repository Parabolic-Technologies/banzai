## Changes since 2.2.0

- The npm package description and keywords describe the CLI as spec-driven AI
  development tooling for Codex and Claude Code, so the package is easier to
  find on npm.
- The npm README is now a compact landing page: value propositions, an
  illustrated strict-workflow walkthrough with an example request, a four-step
  Quick start, a documentation table, and contribution entry points. The
  complete operational reference moved to
  [`documentation/orchestrator.md`](../orchestrator.md) without content
  changes beyond relocated links.
- New guides: [Your first Banzai task](../getting-started.md) with setup
  order, expected outcomes, and troubleshooting, and
  [verification examples](../verification-examples.md) with adaptable
  Node, Python, Go, and mixed-project profiles.
- The root README shares the npm page's positioning, prerequisites, and setup
  order, and corrects the workflow description: a passing review completes a
  strict run, independent review applies to strict work, and the orchestrated
  reviewer returns structured findings while the runner renders the review
  artifact.
- The release-policy documentation block and the related validator and test
  targets moved with the reference to `documentation/orchestrator.md`.
- The containerized CI release-check lanes register the workspace as a Git
  safe directory, and the release check reports Git's failure cause.

No `banzai` CLI behavior, command, contract, configuration schema, or
persisted format changed. Projects on 2.2.0 need no migration.

## Requirements and installation

Requirements are unchanged from 2.2.0: macOS or Linux, Node.js 22.20.0+ within
major 22 or 24.11.1+ within major 24, Git, Codex CLI 0.145.0+, Claude Code
2.1.218+, subscription authentication, and the plugin in both clients.

Install this CLI release with:

```text
npm install --global @parabolic-technologies/banzai@2.2.1
banzai --help
```

The plugin and orchestrator share version **2.2.1**; their installation and
delivery remain separate. The npm README references the illustration and
guides on the `main` branch of the public repository.

## Verification and support

Maintainers use `npm run release:check` for deterministic source validation,
with the same required and advisory GitHub Actions lanes as 2.2.0. Local
checks do not establish hosted CI, public installation, or real vendor
behavior.

Report ordinary bugs through
[GitHub Issues](https://github.com/Parabolic-Technologies/banzai/issues), and
vulnerabilities privately through [SECURITY.md](../../SECURITY.md).
