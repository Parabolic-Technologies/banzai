# Banzai 2.7.1

Strict ADR and plan gates now support required-feedback rework and explicitly
requested independent planning reviews. Reviews are read-only and published as
create-only planning-review-N.md siblings. The planner analyzes findings without
edits; human triage selects options, own instructions or declines before normal
planning applies revisions. Zero findings and all-declined triage restore the
origin gate without an additional model call. Reviewed byte drift fails closed.
Code-review artifacts, continuity and approval-bundle contents remain unchanged.

Two intentional compatibility breaks:

- ADR rework now requires non-empty feedback. Supply `--note` for human CLI
  rework or use the gate-decision v1 stdin document in agent control.
- Agent control is 8.0.0 with capabilities v8 and status v6. Supervisors must
  require the exact new declaration and use gate-decision v1 and planning-triage
  answer v4. Use raw UTF-8 JSON within 64 KiB; never rewrite human text to fit.

The approve-plan parser now rejects unknown, repeated, positional and
`--name=value` arguments before any approval. Documented invocations are
unchanged. An older CLI may silently approve when given unknown new flags;
verify `banzai --version` and the current control capability before using them.

New runs use state v10 and context v2. States v1-v9 and context v1 remain
readable, with no migration or fabricated authority. The current hook executes
only v10. Keep historical documents and start new work. Update CLI and plugin
together when the owner chooses installation; this source change installs,
publishes and executes no live vendor operation. Evaluation/KPI formats gain no
metric. Accepted ADR bodies retain their existing instruction/review protection;
applying planning retains ordinary documentation write grants.
