# Banzai 3.0.0

3.0.0 applies ADR-0045 to the plugin and orchestrator together. Supported
versions are declared in `release-policy.json.compatibility`. Within a major,
new resource versions are additive; at a major boundary exactly one remains
per family. Identifiers keep their existing numbers.

Old instruction-layout recognition and its migration procedure are removed.
Artifact storage is private only; documentation-path work registration and
migration are removed. Version synchronization requires all nine current fields
and a strictly greater target; the 1.19.0 bootstrap and independent
1.18.1/0.8.2 rollback procedure are removed. Completion no longer has a legacy
state/source. Missing canonical evidence is unknown, never inferred completion.
Standalone reviews use `banzai-standalone-review/v1`; runner reviews use
`banzai-feature-review/v4` from snapshot v3 and review-result v2.

KPI v2 reports verification attempt counts, executed and reused checks, reuse
ratio and evidence completeness. Previous KPI v1 outcome tables are removed;
the current evaluation export retains outcome, review and usage evidence for
separate analysis.

Unsupported evidence fails with `RESOURCE_VERSION_UNSUPPORTED`, naming the
resource, found version, supported version and last reading major. Readers do
not normalize, downgrade, repair or write unsupported evidence. Archive restore
preserves bytes but does not make previous-major evidence readable or resumable.

## Operator actions

Before upgrading, use the last 2.x release to finish or explicitly cancel active
runs. Export any evaluation history you need with that release, and preserve
required work/run evidence under your retention and custody policy. Then remove
old `.banzai/runs/` roots and their active pointer from the project. This is an
operator action; upgrading does not delete evidence automatically.

Regenerate `.banzai/config.json` at schema 3 from current configuration defaults,
retaining your intended models and explicitly selected verification profiles.
Every check needs a stable ID. Verification policy is optional: without it,
checks execute fresh. All new runs use state 5, binding v2 and ledger 2.
Start new private work with binding v2; old work bindings are not upgraded.
Run `banzai doctor`, review its project-guidance diagnostics, and resolve partial
instruction layouts through explicit project setup and approved merges before
starting work. Restart installed clients after updating their plugin.

Supervisors require control contract 4.0.0, answer v2, binding v2 and private
layout. Plain escalation is answered by the human through interactive
`banzai answer`; the supervisor then refreshes status. Consultation answers keep
the exact run, request, round and decision identities.

## Release evidence

This note describes the source target and compatibility consequences. Local
verification, independent review, owner release approval, installed-client
confirmation and publication are separate evidence. Matching versions or a
passing local gate do not prove delivery. The rollback target is the last
release of major 2 with its complete source and tooling.
