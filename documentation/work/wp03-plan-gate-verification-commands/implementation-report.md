## Deviations from the brief

- `plugins/banzai/skills/development-plan/SKILL.md` is unchanged. The
  standalone skill reads `policies/plan-task-completion.md` before defining
  strict tasks, and its Document section defers the inventory to that policy,
  so the canonical policy text carries the rule for both the runner and the
  standalone path. Restating it in the skill would duplicate it.
- The brief expected golden prompt digests to change. `prompts.test.ts` pins
  output contracts and legacy repair bytes, not the planning instruction, so no
  digest changed; the new test pins the planning sentence.
- The authority for the instruction change is ADR-0049 §2, which requires the
  checks to be readable in plan review.
- Each check takes two lines instead of one: the facts line, then the command
  on its own detail-indented line, so a long argv stays whole and copyable, as
  in the WP1 failure details.
- At the plan gate every check is required: phase candidates arrive only after
  implementation. The label distinguishes plan obligations from checks the
  project policy requires.
- The runner-level policy merge has no end-to-end test: test repositories use
  configuration schema 2, and only schema 4 carries a task policy. The label is
  covered by the line test; the merge is `selectTaskVerification`, which
  verification already tests.
